# RepoRescue v0.2.0-alpha.2

Second public alpha, following the initial `v0.2.0-alpha` release (package
`0.2.0a1`). This release uses package version `0.2.0a2`; JSON schema remains
`0.2` and is versioned independently.

## Highlights

- Python `requires-python` compatibility diagnosis for a conservative subset of
  final-version comparisons; unsupported constraints receive a limitation notice.
- Project-local `.venv` / `venv` interpreter detection and mismatch warnings,
  without running candidate interpreters.
- Evidence-based `ModuleNotFoundError` diagnosis and limited
  `ImportError: cannot import name ... from ...` symbol failure diagnosis.
  Import names are not automatically mapped to package distributions.
- Controlled startup probing with explicit `--run-startup-probe` CLI opt-in,
  non-zero exit diagnosis, startup timeout handling, and bounded stdout/stderr
  capture. Timeout is an observation, not proof of a hang or readiness.
- Deterministic failure fixtures for regression tests and demonstrations.
- Improved terminal output and reduced exposure of known local paths in terminal
  reports. JSON and captured project output may still contain real paths.
- Bilingual English / Simplified Chinese README and an automated README demo GIF
  generator. Pillow is a documentation tool dependency, not a runtime dependency.
- Updated execution safety documentation and complete source-distribution demo
  materials, including the Chinese README, GIF, and generation script.

## Safety

RepoRescue is safe by default: it does not execute project code unless the user
explicitly opts in. Default diagnosis runs only allowlisted diagnostic commands.
`--run-startup-probe` confirms a CAUTION-risk probe using the absolute current
Python interpreter and root-level `main.py`, with `shell=False`, disabled stdin,
a five-second observation window, and bounded stdout/stderr capture.

Project code can have file, network, service, or other side effects. These controls
are not a sandbox: descendants are not supervised and there is no generic secret
masking or process-tree/resource isolation. Review reports before sharing them.

There is no arbitrary shell execution, automatic pip installation, automatic
repair, or dependency file modification by RepoRescue. Repair previews and
verification plans remain unexecuted.

## Limitations

- Windows First and Python only. Python 3.13.1 has been tested; Python 3.12 and
  Linux/macOS have not been separately verified for this alpha.
- Root-level `main.py` is the only supported startup entrypoint.
- No Repair Executor, Verification Executor, or Rollback.
- No plugin SDK, GUI, or Agent/MCP integration yet.

The package remains dependency-free at runtime, with internal package
`agent_doctor` and CLI `repo-rescue`. The temporary `agent-doctor` compatibility
alias remains available. This is an alpha release, not a stable release.
